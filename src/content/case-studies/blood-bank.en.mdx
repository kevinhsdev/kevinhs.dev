## The problem

A project for the **Object-Oriented Programming with JDBC** course at UMC, in 2026. The mission:
model a blood bank's daily work, that is, **register donors, record donations, track the stock of
each blood type and serve patients**.

The tricky part is the stock. Every donation changes the number of units. If that math depends on
each screen remembering to update the stock, one day someone forgets, and the number on screen stops
matching the blood that actually exists. In a blood bank, that's not just any bug.

## Where I come in

It was a **team of 3**. I took the **DAO layer** and the **MySQL triggers** that update the stock, in
the Patient, Donor, Donation and Stock modules.

## The rules of the game

- **Plain JDBC**, no ORM: the course was about understanding data access under the hood.
- **Object orientation** was graded: models, responsibilities and well-separated layers.
- A course deadline and the work split between three people.

Two more groundwork choices: **one DAO per entity** with a `ConnectionFactory` (screens don't know
SQL and the connection is configured in one place) and **`PreparedStatement` in every query**, with
typed parameters and protection against SQL injection.

## Details I'm proud of

### The database looks after the stock

`EstoqueDAO` only knows how to query. What maintains the `ESTOQUE` table is the trigger fired on
every donation. (The code is in Portuguese, as the course was.)

```java title="src/DAO/EstoqueDAO.java (abridged)"
public List<Estoque> consultarTodos() throws ClassNotFoundException, SQLException {
    Connection con = ConnectionFactory.getConnection();
    PreparedStatement comando = con.prepareStatement("select * from ESTOQUE");
    ResultSet rs = comando.executeQuery();
    // ...builds the list of Estoque (blood type and quantity)
}
```

### Compatibility at a glance

Who can donate to whom, in a single method with Java _switch expressions_.

```java title="src/Model/Compatibilidade.java (abridged)"
return switch (tipoDoador) {
    case "O-"  -> true;                        // universal donor
    case "O+"  -> tipoPaciente.endsWith("+");  // every Rh+
    case "A+"  -> tipoPaciente.equals("A+")  || tipoPaciente.equals("AB+");
    case "B+"  -> tipoPaciente.equals("B+")  || tipoPaciente.equals("AB+");
    case "AB+" -> tipoPaciente.equals("AB+");
    // ...and the negative types
    default    -> false;
};
```

## If I did it again

Looking at the code today (and being honest with my past self), I'd change:

- use `try-with-resources`, since some queries open the connection and never close it;
- update a donation by its own `id`, not by `id_doador`, which changes every donation from that
  donor;
- version the database script (tables and trigger) with the code;
- write tests for `Compatibilidade`, the easiest rule to test and the most expensive to get wrong.
