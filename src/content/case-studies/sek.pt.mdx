## O problema

Sou Jovem Aprendiz na secretaria de uma escola com **cerca de 535 alunos**, do Maternal ao Ensino
Médio. O dia a dia rodava em **planilhas de Excel e documentos de Word avulsos**, espalhados entre
vários sistemas: o acadêmico (desktop), o de captação de famílias, o da Secretaria Escolar Digital,
o da cantina.

Rematrícula, pendências de documentos, contratos, declarações, bolsas, boletos, autorização de
saída... cada coisa morava num arquivo diferente, e nenhum sabia da existência do outro. Toda tarefa
começava com uma caça à planilha certa.

## Onde eu entro

Projeto **pessoal, de iniciativa própria**, feito sozinho: levantamento, arquitetura, código, testes,
documentação e instalação. Uso o **Claude Code como par de programação**, com um documento de
handoff vivo (decisões, armadilhas, roteiro) para cada sessão continuar de onde a outra parou.

## As regras do jogo

O cenário tinha mais restrições do que um speedrun:

- **Sem TI dedicada** e PCs Windows comuns, sem garantia de poder instalar programas.
- **Tem que funcionar sem internet**: a rede da escola não é confiável.
- **Dados de menores**: LGPD pesa mais do que qualquer conveniência.
- **Várias pessoas ao mesmo tempo**: um PC vira servidor e os outros acessam pelo navegador.
- **Integração só por exportação**: sem acesso garantido ao banco do sistema acadêmico, os dados
  entram pelas planilhas `.xlsx` que ele já exporta.
- **Quem mantém pode não programar**: instalar e atualizar têm que ser coisa de dois cliques.

## Detalhes que eu curti

### O conflito, no código de verdade

A tela envia a versão que carregou. Se outra pessoa gravou depois, o servidor responde **409** com o
nome e a hora. No navegador, só os campos alterados são enviados, então se cada um mexeu num campo
diferente, o trabalho dos dois fica.

```js title="app/server.js"
function conferirVersao(atual, b, u) {
  const versao = b._versao,
    forcar = b._forcar;
  delete b._versao;
  delete b._forcar;
  if (versao === undefined || forcar) return;
  if ((atual.atualizado_em || null) === (versao || null)) return;
  if (!atual.atualizado_por || atual.atualizado_por === u.login) return;
  // ...busca o nome de quem gravou
  falha(409, `${nome} alterou isto enquanto você editava.`, {
    conflito: { por: nome, em: atual.atualizado_em },
  });
}
```

### Backup cifrado que cabe no bolso

O backup sai com o sistema aberto (`VACUUM INTO`) e, se tiver senha, cifrado com **AES-256-GCM**:
chave derivada com `scrypt`, sal e IV aleatórios e uma marca no começo para reconhecer o arquivo. A
restauração é em duas etapas: valida, agenda e só troca o banco na próxima abertura, guardando uma
cópia do anterior.

```js title="app/lib/backup.js"
function cifrar(dados, senha) {
  const sal = crypto.randomBytes(16);
  const iv = crypto.randomBytes(12);
  const chave = crypto.scryptSync(senha, sal, 32);
  const c = crypto.createCipheriv("aes-256-gcm", chave, iv);
  const corpo = Buffer.concat([c.update(dados), c.final()]);
  return Buffer.concat([MARCA, sal, iv, c.getAuthTag(), corpo]);
}
```

### O que mais cuida dos dados

- **Login por pessoa**, com perfis, troca de senha obrigatória no primeiro acesso, bloqueio de tela
  validado no servidor e cabeçalho CSP.
- **Sessões no banco** (só o hash do token): reiniciar o servidor não desloga ninguém. Se ele cair,
  aparece uma faixa de "sem conexão" e **o que foi digitado vira rascunho recuperável**.
- **LGPD**: registro de quem consultou cada ficha, exportação de tudo sobre um aluno e descarte que
  anonimiza ex-alunos sem perder a estatística.
- **Dado real nunca vai para o Git**: os modelos são limpos por um script antes de qualquer commit, e
  os testes usam uma demonstração com dados fictícios.

## Se eu fizesse de novo

**Faria um piloto antes.** Construí quatro etapas antes de ter um único módulo rodando com dado real.
Hoje eu começaria por **um módulo só, num piloto de duas semanas**: é isso que prova valor e ganha a
confiança de quem decide.

Próximos passos: **medir o tempo** de cada tarefa antes e depois, para trocar o relato por números, e
seguir evoluindo pelo que a secretaria mais usa.

E o que eu decidi **não** fazer: reescrever em React (meses perdidos para ganhar build e
dependências), levar para a nuvem (dado de menor na internet) e automatizar WhatsApp em massa (a API
oficial é paga e a não oficial derruba o número da escola).
