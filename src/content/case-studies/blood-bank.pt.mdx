## O problema

Projeto da disciplina de **Programação Orientada a Objetos com JDBC** na UMC, em 2026. A missão:
modelar o dia a dia de um hemocentro, ou seja, **cadastrar doadores, registrar doações, acompanhar o
estoque de cada tipo sanguíneo e atender pacientes**.

O ponto delicado é o estoque. Toda doação muda o número de bolsas. Se essa conta depender de cada
tela lembrar de atualizar o estoque, um dia alguém esquece, e o número na tela deixa de bater com o
sangue que existe de verdade. Num hemocentro, isso não é um bug qualquer.

## Onde eu entro

Foi trabalho em **equipe de 3 pessoas**. Eu fiquei com a **camada DAO** e com as **triggers do
MySQL** que atualizam o estoque, nos módulos de Paciente, Doador, Doação e Estoque.

## As regras do jogo

- **JDBC puro**, sem ORM: a ideia da disciplina era entender o acesso a dados por baixo dos panos.
- **Orientação a objetos** como critério de nota: modelos, responsabilidades e camadas bem separadas.
- Prazo de disciplina e trabalho dividido entre três pessoas.

Duas outras decisões de base: **um DAO por entidade** com uma `ConnectionFactory` (as telas não
conhecem SQL e a conexão é configurada num lugar só) e **`PreparedStatement` em todas as
consultas**, com parâmetros tipados e proteção contra SQL injection.

## Detalhes que eu curti

### O banco cuida do estoque

O `EstoqueDAO` só sabe consultar. Quem mantém a tabela `ESTOQUE` é a trigger disparada a cada
doação.

```java title="src/DAO/EstoqueDAO.java (resumido)"
public List<Estoque> consultarTodos() throws ClassNotFoundException, SQLException {
    Connection con = ConnectionFactory.getConnection();
    PreparedStatement comando = con.prepareStatement("select * from ESTOQUE");
    ResultSet rs = comando.executeQuery();
    // ...monta a lista de Estoque (tipo sanguíneo e quantidade)
}
```

### Compatibilidade numa olhada

Quem pode doar para quem, num único método com _switch expressions_ do Java.

```java title="src/Model/Compatibilidade.java (resumido)"
return switch (tipoDoador) {
    case "O-"  -> true;                        // doador universal
    case "O+"  -> tipoPaciente.endsWith("+");  // todos Rh+
    case "A+"  -> tipoPaciente.equals("A+")  || tipoPaciente.equals("AB+");
    case "B+"  -> tipoPaciente.equals("B+")  || tipoPaciente.equals("AB+");
    case "AB+" -> tipoPaciente.equals("AB+");
    // ...e os tipos negativos
    default    -> false;
};
```

## Se eu fizesse de novo

Olhando o código hoje (e sendo sincero com o meu eu do passado), eu mudaria:

- usar `try-with-resources`, porque algumas consultas abrem a conexão e não fecham;
- atualizar a doação pelo `id` dela, e não pelo `id_doador`, que altera todas as doações do mesmo
  doador;
- versionar o script do banco (tabelas e trigger) junto com o código;
- escrever testes para a `Compatibilidade`, a regra mais fácil de testar e a mais cara de errar.
